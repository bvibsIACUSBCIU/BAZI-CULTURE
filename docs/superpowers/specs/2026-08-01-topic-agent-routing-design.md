# 专题 Agent 路由与精简展示设计

## 问题与根因

当前界面展示的五步 Agent 链是前端的固定加载文案，后端也只执行一次统一
`generate()` 后再拼装固定节点。因此它不是实际的多角色工作流。所有入口还
共享同一个六段 `userReport` 数据模型和渲染器；专题和追问会被这套总览式报告
覆盖。服务降级路径中存在长篇模板式报告，违反动态报告规则。

## 目标

每个入口根据主题或用户问题路由到一个专业 Agent；专业 Agent 只生成本次主题
的受约束分析草案，Writer Agent 再据此写成精简回复。前端显示后端实际返回的
执行摘要与专题结果，不显示伪造的内部思考过程。所有盘面事实仍由本地确定性
引擎产生，所有解释仍受规则、事实编号和安全策略约束。

## 调用路径

1. Coordinator 在本地按显式专题和问题意图选择路由：总览、日主五行、事业、
   财富、情感、方法/来源或安全边界。
2. Chart Agent 在本地取得确定性命盘摘要和该路由的事实集合。
3. Specialist Agent 进行一次模型调用，仅分析路由主题；输出结构化草案、
   `factRefs`、限制和反证。
4. Validator 在本地校验事实引用、专题匹配、规则来源及安全措辞。
5. Writer Agent 进行一次模型调用，仅使用已通过校验的草案，输出专题化的精简
   回答；再次通过同一校验器后返回。

总览仍显示五个真实阶段，但只有 Specialist 与 Writer 调用模型；这保证了
“五 Agent 阶段”不把排盘或安全判断交给模型。单次请求最多两次串行模型调用。
如 Specialist 或 Writer 不可用，返回仅由当前命盘事实和限制构成的短结构版，
绝不填充固定解盘段落。

## 数据模型与前端

返回数据新增 `route`、`display` 和 `pipeline`。`display` 是本次的标题、摘要、
章节、反思问题和限制，不再强制包含六个跨主题字段。`pipeline` 仅含服务端实际
执行的角色、状态、职责和结果摘要，不含模型隐藏推理。

前端按 `display` 渲染一个精简专题结果卡；原局总览可包含多个小节，其他专题
和具体问题只展示其路由相关的小节。加载状态使用服务端可执行阶段名称，不再
伪造“思考过程”。

## 验收

- 六个入口映射到正确的路由和专业 Agent；自由提问可被关键词分类，模糊或高风险
  问题走一般/边界路径。
- 同一张命盘的事业、财富、情感、日主五行和自由提问输出拥有不同主题、不同事实
  集合和不同展示内容。
- 每轮最多两次模型调用；模型不可用时的结果只由该主题当前事实动态构成。
- 返回中没有硬编码的长篇 `userReport`、健康诊断或投资建议。
- 所有现有测试及 `node --env-file=.env scripts/test-simulation.mjs` 通过。
